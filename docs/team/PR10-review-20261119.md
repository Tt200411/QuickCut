## 合并前修复的回归

1. **已有任务无法再次确认。** 旧版本的单句需求也会生成三段方案；按新规则重新拆句会与已保存的检索请求冲突。新草案保存完整大纲，旧草案从原检索主查询恢复结构，确认过程不重新调用模型。大纲必须匹配原请求的身份、顺序、文本、预算和 Brief 总时长，不能靠修改草案哈希绕过核对。
2. **长单句的镜头上限不够。** 原有最多两镜头规则会把可用四段十秒素材的三十秒需求限制为二十秒。仅在容量不足时按真实候选时长放宽上限，最多八个；按短候选组合计算，避免因存在一个长候选而拒绝模型择优选择的三个十秒镜头。具体镜头仍由模型选择，原有足够覆盖的短段落上限保持。
3. **返回修改后无法打开上一版剪映工程。** 允许待确认任务打开已生成的旧工程，同时阻止正在生成的新版本与打开操作冲突；打开旧工程不会确认新修改。
4. **导航异步返回覆盖后续操作。** 返回方案的请求绑定原任务及导航顺序，不能把随后选择的任务或页面切回旧状态。
5. **隐藏视频继续播放。** 切换步骤或任务时暂停离开页面的视频。
6. **多段方案标题错误。** 只有旧版三段 ID 使用“开场／展开／收尾”，新段落按编号和原句展示。
7. **全静音首部的预览与导出不一致。** 当选段完全早于实测原声起点时，预览与导出一致保留已知首部静音；旁白、内部缺音和短尾仍严格校验。
